# 个人网站液态金属视觉升级设计

## 状态

- 设计方向：已确认
- 选择方案：B，液态金属光幕
- 实施状态：尚未开始
- 设计日期：2026-07-15

## 背景

当前网站的内容、黑金配色和居中构图可以保留，但首屏主要依赖渐变、网格、二维粒子和淡入动画，空间层次及品牌记忆点不足。

本次升级以视觉呈现为主，不改写网站文案，不重新定义业务，不重组页面内容。首屏采用覆盖背景空间的液态金属光幕，不使用宝石、钻石、球体或其他与业务无关的中心装饰物。

## 目标

1. 在不改变原有内容的前提下，让首屏具备明显的视觉升级。
2. 保留“帮传统企业 / 用 AI 解决真问题”的打字机动画。
3. 建立统一的黑金流体视觉语言，并自然连接后续页面区块。
4. 保证文字、头像和行动按钮始终是首屏的最高视觉优先级。
5. 在桌面端提供空间感和鼠标反馈，在移动端保持稳定、清晰和流畅。

## 非目标

- 不修改首屏或其他区块的业务文案。
- 不调整客户名称、案例数字、认证数量和按钮目标。
- 不增加独立的 3D 宝石、核心球、AI 球体或装饰模型。
- 不引入全站强制平滑滚动。
- 不在本轮重做案例证据链、需求诊断或服务分流。
- 不重新设计网站的信息架构。

## 视觉设计

### 基础构图

沿用现有首屏内容顺序：

1. 头像
2. 身份标签
3. 两行主标题
4. 说明文字
5. 服务客户
6. 行动按钮
7. 关键数据

内容容器、字号层级和主要间距保持现状，仅在必要时做不改变构图的像素级适配。

### 液态金属光幕

液态金属不是独立物体，而是一层覆盖整个首屏空间的动态反光表面。

- 主体集中于画面右侧和背景边缘。
- 文案区域设置深色安全遮罩，防止高光穿过文字。
- 主色使用现有黑金体系：
  - 背景黑：`#080807`
  - 品牌金：`#c9a55c`
  - 高光金：`#ead38d`
  - 深铜色：`#57401b`
- 高光面积应小于首屏可视面积的 18%。
- 最亮区域不得覆盖主标题、说明文字和主要按钮。
- 不使用彩虹、紫蓝渐变或高饱和霓虹色。

### 页面层级

从后到前分为五层：

1. 黑色基础背景与极弱网格。
2. WebGL 液态金属 Canvas。
3. 对比度遮罩、暗角和边缘光。
4. 原有头像、文字、按钮和数据内容。
5. 按钮局部扫光，不使用覆盖文字的前景流体。

液态金属 Canvas 永远位于内容层后方，不允许通过 `z-index` 穿到标题或正文前面。

## 动画设计

### 页面进入

1. 页面加载后，液态金属光幕在 600ms 内从低对比度渐显。
2. 加载约 800ms 后，保留现有打字机动画：
   - 逐字显示“帮传统企业”。
   - 停顿约 400ms。
   - 逐字显示“用 AI 解决真问题”。
3. 液态金属流动不能与打字机动画同时出现明显亮度跳变。

### 环境动画

- 金属纹理持续缓慢流动，完整循环感知时间不短于 12 秒。
- 动画不做明显重复的左右摆动。
- 高光移动速度保持稳定，避免产生视频背景感。
- 粒子仅作为空间辅助，数量和亮度均低于当前视觉主体。

### 鼠标反馈

仅在支持精确指针的桌面设备启用：

- 鼠标位置对 Shader 产生轻微形变。
- 最大位移不超过画面宽度的 2%。
- 使用插值缓动，禁止纹理直接追随鼠标。
- 鼠标离开窗口后逐渐回到中性状态。

### 按钮反馈

- 主按钮悬停时出现一次从左到右的金属扫光。
- 扫光时长为 450-650ms。
- 不循环播放，不改变按钮尺寸。
- 次按钮保持现有描边逻辑，仅增强边缘亮度。

### 滚动衔接

当用户离开首屏时：

- 液态金属亮度逐渐降低。
- 右侧高光带收束为一条较细的金色流线。
- 流线向下连接下一内容区块的视觉边缘。
- 后续区块只保留少量金属边缘或反光，不重复铺满液态背景。

不启用全站平滑滚动。滚动进度只用于驱动视觉参数，不改变浏览器原生滚动行为。

## 技术设计

### 技术栈

- 保持 Astro 现有架构。
- 使用 `three` 创建 WebGL 场景和全屏 Shader 平面。
- 使用自定义 GLSL Fragment Shader 生成液态金属纹理。
- 使用 GSAP ScrollTrigger 驱动首屏退出时的视觉参数。
- 不引入 React，不直接安装 React Bits。
- Paper Shaders 和 React Bits 仅作为视觉及 Shader 结构参考，不复制其页面组件。

### 组件边界

新增以下模块：

#### `src/components/HeroLiquidMetal.astro`

- 输出 Canvas、对比度遮罩和无 WebGL 回退层。
- 管理组件所需样式。
- 不包含首屏文案。

#### `src/lib/liquid-metal-scene.ts`

- 创建和销毁 Three.js 场景。
- 管理 Shader、相机、渲染器、尺寸变化和鼠标输入。
- 暴露滚动进度更新接口。
- 处理暂停、恢复、降级和资源释放。

#### `src/components/Hero.astro`

- 保留现有内容和打字机逻辑。
- 将当前二维粒子 Canvas 替换为 `HeroLiquidMetal`。
- 保留原有 HTML 内容、链接和数据。
- 只增加必要的按钮扫光样式与滚动连接钩子。

### Shader 参数

场景至少支持以下参数：

- `uTime`：流体时间。
- `uPointer`：经过平滑处理的鼠标位置。
- `uScroll`：首屏滚动进度。
- `uResolution`：Canvas 渲染尺寸。
- `uIntensity`：整体亮度。
- `uRightFocus`：右侧高光集中程度。

参数应集中配置，禁止把关键视觉数值散落在动画循环中。

### 生命周期

- 组件进入视口时开始渲染。
- 完全离开视口后暂停 `requestAnimationFrame`。
- 页面进入后台时暂停渲染。
- 页面恢复可见时继续渲染。
- 页面卸载时销毁 Geometry、Material、Renderer 和事件监听器。

## 性能与降级

### 桌面端

- `devicePixelRatio` 上限为 1.5。
- Shader 噪声迭代不超过 5 层。
- 目标帧率为 55-60fps。
- Canvas 不参与页面尺寸计算，避免布局偏移。

### 移动端

- `devicePixelRatio` 上限为 1.25。
- Shader 噪声迭代降为 3 层或使用简化材质。
- 关闭鼠标交互和辅助粒子。
- 目标帧率不低于 40fps。
- 当设备性能明显不足时，降级为低频率渲染或静态金属渐变。

### 无障碍与回退

- `prefers-reduced-motion: reduce` 时只渲染静态画面。
- WebGL 初始化失败时显示 CSS 黑金径向渐变。
- 动画关闭后仍显示完整文案和按钮。
- Canvas 设置为装饰性元素，不进入键盘焦点顺序。

## 数据流

```text
窗口尺寸 / 指针位置 / 滚动进度
                ↓
     liquid-metal-scene.ts
                ↓
         Shader Uniforms
                ↓
       WebGL Canvas 渲染
```

首屏内容与 WebGL 场景没有数据依赖。即使场景初始化失败，原有内容仍正常显示和操作。

## 错误处理

- Three.js 动态初始化使用 `try/catch`。
- 初始化失败时给根节点增加 `data-webgl-fallback`。
- Shader 编译失败不得阻塞首屏其他脚本。
- ResizeObserver 和 IntersectionObserver 不可用时使用窗口事件与常驻渲染作为回退。
- 任何错误不得影响打字机、锚点跳转和联系按钮。

## 验收标准

### 内容

- 首屏所有原文案逐字保持不变。
- 头像、客户名称、按钮链接和四项数据保持不变。
- 打字机动画的两段文字、顺序和停顿保持不变。

### 视觉

- 1920×1080、1440×900 和 390×844 下文字均不被遮挡。
- 液态金属主要集中在右侧和背景边缘。
- 页面中不存在宝石、球体或无业务关系的中心装饰物。
- 首屏第一视觉焦点仍是标题，而不是 Shader。
- 从首屏滚动到下一部分时没有突兀断层。

### 功能

- 两个首屏按钮正常跳转。
- 鼠标反馈平滑，无明显抖动。
- 页面切换后台后渲染暂停。
- `prefers-reduced-motion` 下动画正确降级。
- WebGL 不可用时内容完整可用。

### 性能

- `npm run build` 通过。
- 桌面端连续观察 10 秒无明显掉帧。
- 移动端没有持续高温、页面卡死或滚动阻塞。
- 浏览器控制台无错误和资源泄漏警告。

## 验证方案

1. 执行 `npm run build`。
2. 启动本地 Astro 开发服务器。
3. 使用 Playwright 检查桌面和移动端截图。
4. 检查 Canvas 像素方差，确认场景不是空白画布。
5. 模拟鼠标移动，验证 Shader 只有轻微形变。
6. 模拟滚动，验证光幕收束且不影响原生滚动。
7. 模拟 `prefers-reduced-motion`。
8. 禁用 WebGL，验证 CSS 回退和首屏内容。

## 回滚方案

实现时保留现有 `hero-bg`、`hero-grid` 和二维粒子代码的独立版本。若新场景存在兼容性或性能问题，可以移除 `HeroLiquidMetal` 引用并恢复原有背景结构，不影响首屏内容。

# 个人网站全站章节式视觉叙事设计

## 状态

- 设计方向：已确认
- 选择方案：B，章节式视觉叙事
- 视觉主线：连续液态金属，随章节改变形态
- 内容范围：保留现有文案、区块顺序和核心布局
- 实施状态：尚未开始
- 设计日期：2026-07-15

## 背景

首屏已经完成液态金属视觉升级，保留了原有内容与打字机动画，但 WhyMe、ROI、案例、证书、服务、流程、FAQ 和联系区仍主要依赖静态卡片、基础淡入和计数动画。首屏与后续内容之间存在明显的视觉强度断层，用户离开首屏后很难继续感受到统一的视觉主题。

本轮升级的重点不是改写内容，而是让液态金属视觉语言贯穿整页，并根据内容功能在不同章节中变化形态，形成一条从能力证明到业务转化的连续视觉旅程。

## 目标

1. 让全站而非只有首屏具备明显的视觉升级。
2. 保留现有文案、信息结构、链接、案例数字和 ROI 计算逻辑。
3. 建立“能力 → 收益 → 成果 → 资质 → 服务 → 交付 → 联系”的滚动叙事。
4. 让动效服务于信息理解，不遮挡文字，不降低可读性。
5. 桌面端提供明显的空间层次和交互反馈，移动端保留核心视觉变化。
6. 复用现有 Three.js 和 GSAP，不增加新的大型前端依赖。

## 非目标

- 不修改网站业务定位与服务内容。
- 不重排页面区块，不新增独立页面。
- 不重做案例证据链，不补充新的案例图片或客户材料。
- 不修改 ROI 计算公式和估算参数。
- 不增加宝石、钻石、AI 核心球等无业务关系的中心装饰物。
- 不使用横向滚动、全站强制平滑滚动或需要用户学习的新导航方式。
- 不让每个区块拥有互不相关的独立特效。
- 不执行部署、推送或上线。

## 整页视觉叙事

液态金属从首屏开始，随滚动经历以下形态变化：

1. **Hero：液态光幕**
   - 全屏液态金属在背景中缓慢流动。
   - 保留“帮传统企业 / 用 AI 解决真问题”的打字机动画。
   - 离开首屏时，光幕亮度降低并收束成三条细金属流线。

2. **WhyMe：三条能力线路**
   - 三条线路分别进入“懂业务、懂 AI、能落地”。
   - 卡片被线路依次激活，数据随激活开始计数。
   - 三条线路在区块底部重新汇合。

3. **ROI：输入驱动能量波纹**
   - 汇合后的线路进入三个滑块轨道。
   - 用户拖动滑块时，金色流体沿轨道移动。
   - 结果变化产生液态波纹和数值脉冲。

4. **Cases：成果档案轨道**
   - 波纹转为纵深金属轨道。
   - 案例卡片沿近景与远景错层进入。
   - 当前案例对应的轨道节点和数据区域被点亮。

5. **Certificates：证书展陈反光**
   - 轨道扩散为证书展墙的金属边缘光。
   - 证书卡片产生轻微 3D 倾斜和随角度变化的反光。
   - 离开区块时，反光重新汇成三条服务线路。

6. **Services：三条服务线路**
   - 三条线路分别进入三张服务卡。
   - 悬停某张卡片时，对应线路增强，其他线路降低亮度。

7. **Process：单一交付路径**
   - 三条服务线路重新汇成一条合作轨道。
   - 01 至 04 四个节点按滚动进度依次点亮。

8. **FAQ：主动降噪**
   - 全局视觉强度降低。
   - 展开问题时仅保留细边缘流光和必要的状态反馈。

9. **Contact：视觉收束**
   - 全页线路最终汇入二维码区域。
   - 二维码外围形成缓慢流动的金属边框。
   - 鼠标接近时线路轻微聚拢，形成明确的页面终点。

## 区块设计

### WhyMe

- 保留三张卡片及其文案、图标和数据。
- 卡片默认保持可读，不依赖动画才能显示内容。
- 进入视口后，三条线路按 120-180ms 的间隔依次到达卡片。
- 线路到达后触发卡片清晰化、轻微前移和数字计数。
- 桌面端卡片最大倾斜角为 4 度，移动端关闭倾斜。
- 线路不得穿过正文文字，只能经过卡片边缘、图标区域或数据分隔线。

### ROI

- 保留现有双栏布局、滑块范围、公式、结果和 CTA。
- 三个滑块使用独立的流体填充进度，流体长度与当前值同步。
- 每次输入变化只触发一次短脉冲，不连续闪烁。
- 右侧结果区增加低对比度液态波纹背景。
- “年度综合节省”更新时短暂放大至 1.04 倍，并出现一次 450-650ms 金属扫光。
- 数字更新与视觉反馈必须在同一动画帧内开始。
- `aria-live` 行为保持不变。

### Cases

- 保留六张案例卡片和双列网格，移动端保持单列。
- 左列从轻微近景进入，右列从轻微远景进入，位移不超过 28px。
- 卡片进入焦点区域时，关联轨道节点点亮，内部数字再开始计数。
- 悬停卡片时只增强当前卡片，不改变其他卡片尺寸或网格位置。
- 不使用横向轮播，避免降低案例扫描效率。

### Certificates

- 保留七张真实证书图片、名称、机构和日期。
- 桌面端保持三列展陈，卡片允许最大 5 度倾斜。
- 证书图片反光仅作用于图片边缘和表面，不覆盖名称和说明文字。
- 点击图片打开大图查看器，支持关闭按钮、遮罩点击和 `Escape`。
- 手机端保持紧凑网格，关闭跟随指针倾斜，保留点击放大。
- 大图查看器必须锁定背景滚动，并正确恢复焦点。

### Services

- 保留三张服务卡、推荐标识、交付物与 CTA。
- 三条线路分别对应三张卡片。
- 当前悬停或键盘聚焦的服务卡提升线路亮度。
- 推荐卡片只做轻微前置和边缘增强，不改变整体网格高度。
- 按钮保持可点击，线路层设置 `pointer-events: none`。

### Process

- 桌面端保持四列流程，移动端使用纵向流程。
- 连接线根据区块滚动进度从 0% 生长至 100%。
- 已经过的节点保持稳定亮度，当前节点出现一次脉冲，未到达节点保持暗态。
- 动画不改变节点尺寸，避免布局跳动。

### FAQ

- 保留现有六个问题和单项展开逻辑。
- 打开问题时，一条细流光沿卡片边缘通过一次。
- 不增加 3D Canvas 或高频环境动画。
- 键盘操作、`aria-expanded` 和 `aria-hidden` 逻辑保持正常。

### Contact

- 保留现有标题、说明、二维码和四个平台链接。
- 全局线路从背景边缘汇入二维码外围，不得穿过二维码像素区域。
- 二维码外围金属边框缓慢流动，周期不短于 8 秒。
- 指针接近二维码时只增强聚拢程度，不放大二维码超过 1.02 倍。
- 社交卡片按顺序进入，但不延迟用户点击。

## 技术架构

采用“一个全局视觉场景 + 多个区块交互模块”的结构。

### 全局视觉场景

现有 Hero 液态金属场景扩展为全页视觉控制器，负责：

- 液态光幕。
- 三条能力和服务线路。
- ROI 波纹的背景响应。
- 案例轨道。
- 流程连接线。
- 联系区收束。

全局 Canvas 固定在页面背景层，不参与布局，不接收指针事件。Canvas 的可见强度和形态由当前章节状态与滚动进度控制。

### DOM 动效

以下效果使用 CSS 和 GSAP，而不是增加独立 WebGL 场景：

- 卡片进入和轻微空间错层。
- 卡片倾斜与边缘反光。
- 数字脉冲和扫光。
- 滑块流体填充。
- 流程节点状态。
- FAQ 边缘流光。
- 证书大图查看器。

### 章节控制器

新增统一章节控制器，职责包括：

- 注册页面各区块。
- 读取区块进入、离开和滚动进度。
- 将当前章节映射为全局场景状态。
- 暂停屏幕外的局部动画。
- 响应移动端、低性能模式和减少动画偏好。

建议的章节状态：

```text
hero
whyme
roi
cases
certificates
services
process
faq
contact
```

每个章节只提供标准化状态，不直接操作其他章节的 DOM。

## 组件边界

### `src/components/VisualStoryLayer.astro`

- 输出全局 Canvas、遮罩和无 WebGL 回退层。
- 位于页面内容后方。
- 不包含任何业务文案。

### `src/lib/visual-story-controller.ts`

- 初始化章节观察器。
- 计算当前章节和标准化滚动进度。
- 将状态发送给 WebGL 场景和局部动效模块。
- 管理页面可见性、减少动画和资源释放。

### `src/lib/liquid-metal-scene.ts`

- 在现有首屏场景基础上增加章节状态和形态插值。
- 维持一个 Three.js Renderer、Scene 和动画循环。
- 暴露 `setSection()`、`setProgress()`、`setPointer()` 和 `destroy()`。

### 区块组件

- `WhyMe.astro`：增加线路目标点和卡片激活钩子。
- `ROICalculator.astro`：增加滑块进度变量和结果脉冲钩子。
- `Cases.astro`：增加轨道节点及当前案例状态。
- `Certificates.astro`：增加反光层和大图查看器。
- `Services.astro`：增加线路选择状态。
- `Process.astro`：增加连接进度和节点状态。
- `FAQ.astro`：增加一次性边缘流光。
- `Contact.astro`：增加二维码收束目标。

各区块仍独立维护自己的内容与局部样式，不直接导入 Three.js。

## 数据流

```text
滚动位置 / 当前视口 / 指针 / 输入控件
                    ↓
        visual-story-controller.ts
                    ↓
        标准化章节状态与进度
             ↙              ↘
liquid-metal-scene.ts      区块 DOM 状态
             ↓              ↓
       全局 Canvas       CSS / GSAP 动效
```

ROI 输入值只影响 ROI 的局部视觉参数，不修改全局业务数据。全局场景初始化失败时，所有 DOM 内容、滑块、FAQ、链接和二维码仍可正常使用。

## 性能与降级

### 通用原则

- 全站只保留一个 WebGL Renderer。
- 不为单个区块创建额外 Canvas。
- Canvas 固定在视口后方，避免触发布局重排。
- 页面失焦时暂停渲染。
- 没有视觉变化时允许降低帧率。
- 线路、波纹和反光只使用装饰层，不参与点击。

### 桌面端

- `devicePixelRatio` 上限为 1.5。
- 目标帧率为 55-60fps。
- 卡片倾斜只在支持精确指针的设备启用。
- 同一时刻最多一个区块使用高强度局部动画。

### 移动端

- `devicePixelRatio` 上限为 1.25。
- 减少线路数量、波纹层数和 Shader 迭代。
- 关闭跟随指针倾斜和复杂景深。
- 保留章节点亮、滑块流体、流程进度和二维码收束。
- 目标帧率不低于 40fps。

### 减少动画与回退

- `prefers-reduced-motion: reduce` 时取消位移、倾斜和连续流动。
- 保留静态金属边缘、当前状态高亮和必要的表单反馈。
- WebGL 初始化或 Shader 编译失败时使用 CSS 黑金流线背景。
- 任何降级不得隐藏内容或阻止交互。

## 错误处理

- 全局视觉初始化使用 `try/catch`，失败时设置回退状态。
- 章节目标不存在时跳过该章节，不阻塞其他区块。
- GSAP 不可用时回退到 CSS 状态切换。
- `IntersectionObserver` 不可用时使用节流后的滚动位置计算。
- 证书图片加载失败时显示现有替代文本和中性占位背景。
- 大图查看器关闭时无论通过按钮、遮罩或 `Escape`，都必须恢复滚动和焦点。
- 视觉错误不得影响 ROI 计算、FAQ 展开、锚点导航和外部链接。

## 验收标准

### 内容与结构

- 页面所有现有文案保持不变。
- 区块顺序、链接、二维码、证书、案例数字和 ROI 公式保持不变。
- 首屏打字机动画继续正常运行。
- 页面内容不依赖动画才能阅读。

### 视觉

- 从 Hero 到 Contact 存在可感知的连续金属视觉主线。
- 每个核心区块有明确但不同的章节状态。
- 视觉元素不穿过正文和二维码有效区域。
- 页面不存在宝石、球体或无业务关系的中心装饰。
- FAQ 明显比核心展示区更克制。

### 交互

- ROI 滑块变化时，数值与视觉反馈同步。
- 证书可以通过鼠标、触控和键盘打开与关闭。
- 服务卡悬停和键盘聚焦都能切换对应线路。
- 流程节点按滚动顺序点亮。
- 所有按钮、链接、FAQ 和二维码保持可用。

### 响应式

- 1920×1080、1440×900、390×844 下无文字遮挡和横向溢出。
- 移动端不出现过度倾斜、重度景深或滚动卡顿。
- 证书区在手机端高度得到控制，图片仍可辨认并可放大。

### 性能

- `npm run build` 通过。
- TypeScript 检查通过。
- 桌面和移动端控制台无运行时错误。
- Canvas 像素检查确认场景不是空白。
- 连续滚动整页时无明显长时间掉帧。
- 页面失焦后渲染暂停，返回后正确恢复。

## 验证方案

1. 执行生产构建与 TypeScript 检查。
2. 启动本地生产预览。
3. 使用 Playwright 检查桌面、平板和手机视口。
4. 对每个章节记录进入、焦点和离开三种状态的截图。
5. 检查全局 Canvas 像素方差和章节状态变化。
6. 模拟 ROI 滑块输入，核对数值与视觉同步。
7. 检查证书查看器的鼠标、触控、键盘和焦点恢复。
8. 模拟 `prefers-reduced-motion` 和 WebGL 失败。
9. 检查页面失焦暂停、恢复和资源释放。
10. 检查所有锚点、按钮和外部链接。

## 实施顺序

1. 建立全局章节控制器和全页视觉层。
2. 将现有 Hero 场景接入章节状态。
3. 实现 WhyMe 与 ROI，确认视觉主线和交互反馈。
4. 实现案例轨道与证书展陈。
5. 实现服务线路与合作流程。
6. 实现 FAQ 降噪和联系区收束。
7. 完成移动端降级、无障碍和性能优化。
8. 完成整页自动化与视觉验证。

## 回滚方案

- 各区块通过独立类名和初始化钩子接入视觉系统。
- 移除全局视觉层和章节控制器后，原有内容布局仍可正常显示。
- ROI 原计算函数、FAQ 展开逻辑和链接行为不与视觉控制器耦合。
- 若某个区块存在性能或兼容性问题，可单独关闭该区块的增强效果，不影响其他章节。

本规格获用户审阅确认后，下一步只编写实施计划。实施页面修改、提交代码、推送和部署均需要遵循用户的独立授权范围。
